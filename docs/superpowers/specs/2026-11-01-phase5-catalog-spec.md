## Problem Statement

Six things stand between today's catalog and the Phase 6 onboarding of 30 channels:

1. **The assignable catalog is 7 templates covering 2 niche clusters.** The visual catalog holds 18 families (`studio/lib/templates-catalog.js`: documentary-frames, editorial-headlines, timeline-history, map-journeys, photo-stories, kinetic-typography, beat-synced-type, quote-cards-premium, code-product-demos, explainer-diagrams, browser-chrome, finance-explainers, stats-counters, chart-animations, podcast-audio, vertical-safe-zones, retro-vhs, transitions), but only 7 carry registry metadata (`studio/lib/template-registry.data.js`): 4 history + 3 finance. There is **nothing to assign** in 8 of the 10 launch niches (travel, tech/AI, science, psychology, motivation, productivity, health/fitness, business). Phase 6's "adding channel = data rows, zero code" promise is unmeetable for those niches until the catalog exists.
2. **Story structure lives in the brand kit, not in templates.** The script's shape (hook rules, point count, line length, title pattern) comes from the kit's `script` block (`youtube-engine.mjs:767–789`, the `SC` fields). Assigning a different template changes governance (preflight, dedupe thresholds, review class, thumbnail picking) but **not the story the brain writes**. The monetization policy's own safe harbor — "each video has a distinct storyline, focus, or concept" (`research/platform-niche-template-system-2026-10-24.md` §1.2) — requires distinct structures to be a template property, not an accident of which kit a channel happens to wear.
3. **42 thumbnail designs exist but none of them are registry-assignable.** The v2 pattern (`studio/lib/thumb-templates-v2.js` — one parametric renderer + `studio/lib/thumb-catalog.json`, 42 entries in 12 style categories) is reachable only through the Studio gallery routes (`/api/thumbs/*`). Production thumbnail candidates are staggered video frames (`thumbFrameOffset`, `youtube-engine.mjs:875`); no template registry, no per-niche sets, no brand-token binding. Master plan §1.2 promised "expose as catalog; per-niche sets; N-candidate generation + pick" — not delivered.
4. **No template is ever DECLARED accepted.** Nothing records, per template, whether it actually generates a valid script, whether the variation gate holds on it, and whether its review class routes correctly. A catalog that fills with untested entries is a liability at 30 channels (one template bug = 30 bad videos/day — own-portfolio research §5.4).
5. **The weekly documentary lane has one hard-coded shape — and no template plumbing.** Cold open + ≥5 chapters + outro is pinned in code (`yt-deepdive.mjs:82` `validEpisode`); the doc lane's brain call does not thread a template id, thresholds, structure sections, or a review-class derivation — none of that exists there today.
6. **Language-parameterized templates are blocked on an undecided voice.** Urdu has exactly two candidate paths — the open-source Piper `ur_PK` voice (quality never verified) and Azure's `ur-IN`/`ur-PK` neural voices — and no decision, no listening test, no template (research cited in S5).

## Solution

Five slices. S1–S4 build/author; S5 is a documented decision point with no build.

**S1 — The catalog authoring system.** A template gets authored as registry DATA (one new block in `studio/lib/template-registry.data.js`, bound to an existing catalog family), passes the existing validator, syncs via the existing CLI, and becomes panel-assignable. Schema additions (small, backward-compatible): a `template_id` separate from the visual `family`, a required-on-new `story_structure` block that constrains the EXISTING shorts skeleton via point slots, and a `disclaimers` list inside `safety` with deterministic enforcement. A written QUALITY BAR governs variation rules and safety blocks. The brain's dedupe tiering is made fail-closed for EVERY review class (today only finance is — D3). A per-template QA gate defines what ACCEPTED means, including the owner's own eyes on a forced generation. Channels hold ONE active assignment; changing templates is a swap (D19).

**S2 — The 32-entry catalog plan, pilot-first.** One template (myth-vs-money) is authored first, structure-faithful to the money-rulebook kit's current format, proven end-to-end on the live MR channel via a SWAP, soaked for a day — THEN the remaining 24 templates are authored in batches (7 existing + 1 pilot + 24 new = 32: 27 video + 5 doc ≥ 30). Structures come from the niche research's concept table (§2.1: 22 named concepts, each expressed as story structure × visual treatment × workflow difference).

**S3 — The thumbnail template registry.** The 42-design catalog is exposed as a `thumbnail_templates` registry (NEW data file + loader mirroring the video registry pattern): per-niche sets, brand-kit token binding (the renderer already accepts accent/shade/brand/face inputs), a rotation rule so consecutive uploads don't reuse a layout, and wiring into the EXISTING Phase 4 pick flow (candidates → `/review` → `thumbnails.set` swap). Candidate 1 stays today's frame thumbnail — regression-pinned. The launch set uses only `needsPhoto: false` designs (Ruling 6).

**S4 — Documentary-lane templates.** The weekly lane's shape becomes template DATA: section plan (cold open, chapter count/minimums, outro), title pattern, review class — supported by a NAMED threading slice in `yt-deepdive.mjs` (thresholds, gating, structure, class derivation) that lands BEFORE any doc template's QA. Five doc entries launch (one per likely doc niche), reusing the existing `validEpisode` contract and SRT captions unchanged.

**S5 — The Urdu deferral, made explicit.** No language-parameterized templates are authored. The decision point is documented with the two voice options and a 30-minute owner listening test (sample clips, blind scoring, a decision rule) that can run any day — no build until the decision lands.

## User Stories

1. As the owner, when I open the panel for a health channel, I want 2–3 assignable templates to choose from — evidence-tiered habit stories, mandatory disclaimers — and assigning one to be a plain swap of the old template, so a fitness launch is: pick ONE, swap, done. A data task, not a coding session.
2. As the owner, I want every template to carry its own story structure and no-repeat rules, so two channels sharing one visual family still produce visibly different videos — the difference YouTube's reviewers can see.
3. As the owner, I want each new template to come with a filled QA row — including MY OWN read of a forced generation and a title-pattern check — so "in the catalog" always means "proven working and human-read", never just "present".
4. As the owner, I want thumbnail sets per niche bound to each channel's brand colors, so 30 channels get distinct looks from data and my thumbnails never repeat back-to-back.
5. As the owner, I want the weekly documentary for each niche to follow its own section plan, so the longform lane isn't one shape wearing different hats — and I want a loud skip, never a shorts-shaped template silently rendered as a documentary.
6. As the owner, I want a one-page Urdu decision card (two voice options, listening test, decision rule), so the language-template question is a 30-minute decision, not an open loop.
7. As staff, I want to browse the full catalog filtered by niche and prepare assignments, while fail-closed approval and template authoring stay owner-only.
8. (Dormant) The client role gains nothing in Phase 5 — no SaaS work (scope pivot: own-portfolio-30).

## Implementation Decisions

### S1 — The catalog authoring system

- **D1 — Template identity separates from visual family (schema v2 — OQ-1 adopted).** Today a registry entry IS a family id — 7 families registered out of 18 means at most 18 assignable templates ever, and two niches needing the same visual with different stories cannot share it. Decision: registry entries gain an optional **`template_id`** plus a **`family`** field naming the visual family (which must exist in `TEMPLATES_DATA`). Key = template_id; when absent, template_id defaults to the family id (the existing 7 keep their identity, assignments, and pinned majors untouched). `family` remains the gallery join and the format-truth source (the existing rule "formats derived from the family's aspectRatios — never declared beyond what the family ships" is kept verbatim). **Honest file count for this slice (~10 files, named):** `studio/lib/template-registry.js` (validator), `studio/lib/template-registry.data.js` (data), `studio/lib/template-registry-db.js` (assignment identity switches to template_id), `sync-template-registry.mjs`, `lib/template-preflight.mjs:145`, `lib/review-gate.mjs` (meta lookup), `youtube-engine.mjs` (resolveTemplateId/registryThresholds), the Studio registry browser + channel panel + wizard picker, and the test suites. **The indeterminacy this ruling avoids, named:** `resolveTemplateId` (`youtube-engine.mjs:642`) calls `getActiveAssignment(channelId)`, which returns "the first active row" when a channel holds several (`template-registry-db.js:250-261`) — with two assignments the brain would gate on an ARBITRARY template. That is why Phase 5 keeps one active assignment per channel (D19) rather than building multi-template selection now.
- **D2 — `story_structure`: point-slot constraints on an IMMUTABLE skeleton (OQ-7, refined per review).** The shorts JSON contract is immutable and stays exactly what the validator enforces today — `hook`, `thumb_headline`, `points[≥4]`, `closing` (`validShortsScript`, `youtube-engine.mjs:749`); the kit's `script` block fixes the point count (money-rulebook: 4) and line length (9–12 words). A template NEVER changes that shape. Its `story_structure` (required on new entries; absent/optional for the legacy 7) authors: for shorts, `beats[]` — **point-slot constraints**, where `beats[i]` names what numbered point i must BE (myth-vs-money: slot 1 = the popular belief, slots 2–3 = the reversal evidence, slot 4 = what-to-do payoff), with an authoring rule beats ≤ the kit/lane point count; `hook_classes[]` (allowed hook types); `title_patterns[]`; `payoff_rule`. For long/doc, `sections[]` (e.g. `cold_open, chapters:8, exhibits, outro`) with `chapter_min_words` (today's floor is 70 — `yt-deepdive.mjs:82`). **Prompt assembly, specified line-by-line (today's lines at `youtube-engine.mjs:767–789`):** `styleLine` unchanged (kit-owned); `themeLine` unchanged; `trendBlock` unchanged; `hookRule` — the kit line stays, the template's `hook_classes[]` APPENDS one constraints line; `pacingRule` unchanged (kit-owned); `titleRule` — the template's `title_patterns[]` REPLACE the kit title line when declared, else the kit line stays [T2a Ruling: REPLACE — two conflicting MUST-title commands would make QA row (h) unsatisfiable]; `structureLine` — REPLACED by the template's beat plan rendered as numbered point-slot constraints when the template declares one, else today's kit line; the JSON-contract line is untouched; the brain `/context` section stays appended last. Unassigned channels keep today's byte-identical prompt. Consumption is one named code slice on the shorts side (the template meta is already resolved at `youtube-engine.mjs:800`) plus the doc-lane threading slice (D15).
- **D3 — The variation-rules QUALITY BAR — and the REAL brain tiering, stated (adversarial C2).** Every rule must name (a) the no-repeat OBJECT — subject, hook, stat, timeline span, dataset, tactic — (b) a lookback window ("channel's last 5 videos", "last 10 headlines"), and (c) where it is enforced: the variation gate (similarity), the title gate, the seed rotation, or the review desk. This mirrors the strongest existing entries (e.g. `timeline-history`'s "no repeated timeline span" — `template-registry.data.js:51-55`). Vibe words ("feels fresh") fail authoring review. **What the gate ACTUALLY enforces today, verified:** per-template similarity thresholds (defaults 0.85 within-channel / 0.90 cross-channel, overridable per template — `youtube-engine.mjs:622–634`) plus the title dedupe and seed rotation; the rules' prose is read by humans and the review desk. **The tiering gap the review caught:** a BLOCK verdict from `/dedupe` only stops generation when the template is finance-gated (`youtube-engine.mjs` dedupe branch: `BLOCK && financeGated → retry/continue`); for ANY other class a BLOCK is **downgraded to WARN and the script ships**. That is wrong for every new `medical` template this phase authors. **Named fix (one line, in T1):** the fail-closed branch extends from `financeGated` to ANY non-empty `review_required`; classes without a review class keep today's downgrade behavior. **Authoring bar that rides it:** every `medical`-class template pins tighter thresholds in its registry block — `variation_threshold ≤ 0.80` (and `cross_channel_threshold ≤ 0.85`), tighter than the defaults, matching the doc lane's pooled whole-episode chunk semantics.
- **D4 — `safety` extends with `disclaimers[]` — deterministic enforcement (adversarial H1).** Vocabulary stays the validator's four classes — `['health','finance','medical','all']` (`template-registry.js:9`). Authoring rule: anything touching bodies/medicine ⇒ `medical`; money/investing ⇒ `finance`; `all` = gated for any reason; `health` remains valid but unused in v1 (OQ-6). `disclaimers[]` carries fixed verbatim texts (health: "Education, not medical advice."; finance: "Education, not financial advice." — the tax-shield kit's "Education, not advice" pattern, `yt-brands/brands.mjs:217`); required for every `medical`/`finance` template. **Enforcement is machine-written, not hoped-for:** (a) the upload DESCRIPTION gains each fixed text appended in code at publish time — the narration keeps creative freedom, the DESCRIPTION carries compliance; (b) at script save, a contains() check verifies the fixed text is present in the record's publish payload (narration or the machine-appended description) — a finance/medical script missing its disclaimer FAILS the save (fail-closed, same posture as "a dup-blocked script is never saved", QA Row T5b-1). The `/review` desk sees the disclaimer line in the record.
- **D5 — The authoring pipeline (OQ-2 adopted).** Per template: (1) an LLM drafting pass produces the registry block from this spec's map (D7) + the niche research §2.1 concept row, following D3/D4 bars; (2) the OWNER reviews against a plain-English checklist (Does the story differ from the niche's other template? Could you tell from the rules what must never repeat? Are the disclaimers right?); (3) machine gates: `node sync-template-registry.mjs --dry` (validator, exit 1 on any bad block) + the per-template QA gate (D6); (4) sync + panel-assign. The owner never writes JSON from scratch; nothing ships owner-unreviewed.
- **D6 — The per-template QA gate: what ACCEPTED means.** A template is ACCEPTED when ALL rows pass, quoted into the phase QA file: (a) dry-sync validates the block; (b) assignment validation passes against a niche-matched channel (existing codes: `niche_mismatch`/`format_mismatch`/`missing_capability`… `template-registry.js:233`); (c) ONE forced generation produces a script whose shape matches `story_structure` (spot-check in plain English); (d) the variation gate ran with the template's thresholds; (e) where the class is `medical`/`finance`, the script HELD at `/review` (per-CLASS live proof, not per-template — Drill B); (f) where picking is on, candidates emitted; **(g) the OWNER READS the forced generation** — a human quality pass, because an LLM drafted it; **(h) the produced title matches the template's `title_patterns`**. Discipline: force_doc dispatch + state edits + test today — no drill waits for a calendar day (owner directive).
