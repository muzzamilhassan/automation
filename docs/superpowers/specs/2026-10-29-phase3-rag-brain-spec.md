## Problem Statement

The script writers (documentary + Shorts) start from zero memory every run: they don't know which of the owner's past videos performed well, what topics were already covered, or which hooks/structures were used across the 15-channel network. YouTube's inauthentic-content policy (renamed Oct 2025) demonetizes templated/repetitive output, and the only anti-repetition defense today is human memory. Compounding this: the system never durably stored full script TEXT — state files hold only titles — so the past is not even embeddable today. The owner's channels need scripts that improve over time and can PROVE they don't repeat.

## Solution

A **memory brain** that is also the **corpus of record**: every published script's full text, its performance numbers, and the research corpus are embedded into a vector index (Neon pgvector — already in the owner's database). Before writing, the renderer asks the brain for the most similar past videos + their stats, and writes with that context. After writing, the brain checks the new script's **semantic similarity** to past scripts — too similar = BLOCKED, the writer retries. Everything runs **inside CI/cloud jobs** — zero dependency on any personal machine (owner requirement, 2026-10-29). Honest limits (from the adversarial review): the memory starts nearly empty and grows with each publish; the duplicate gate is a safety tripwire + evidence generator, not a quality engine — the primary quality levers remain the template variation rules and the retry guidance.

## User Stories

1. As the owner, I want the writer to see my most similar past videos and their performance before writing, so that new scripts reuse what worked and avoid what didn't.
2. As the owner, I want near-duplicate scripts blocked automatically, so that no channel publishes content that risks the inauthentic-content policy.
3. As the owner, I want cross-channel repetition *warned* (and blocked only where a template marks it blocking), so that my 15 channels can't quietly converge without me seeing it.
4. As the owner, I want the memory to include the research corpus, so that scripts cite the documented sources instead of generic claims.
5. As the owner, I want a similarity score recorded for every published script, so that I can PROVE variation if YouTube ever reviews a channel.
6. As the owner, I want the whole memory system to run in CI/cloud, so that shutting my laptop for a month changes nothing.
7. As the owner, I want failed memory lookups to degrade to today's behavior (write without memory) with a visible warning, so that the system never goes dark because the brain is down — except finance-gated templates, where an unreachable dedupe gate blocks rather than risks a policy-violating publish.
8. As the owner, I want the variation threshold configurable per template, so that strict finance templates can be tighter than loose quote channels.
9. As the owner, I want the memory index to rebuild idempotently, so that re-running the indexer never duplicates vectors or loses refreshed performance data.
10. As the owner, I want the brain's cost to be ~zero and bounded (local ONNX embeddings in CI, no embedding API, capped install/model-load time, connection-safe against the Neon ceiling), so that memory scales with the network for free without eating my CI minutes.

## Implementation Decisions

- **D1 — No framework; ONNX runtime, not torch; model-loading budget.** Plain Python + Neon pgvector (research decision 2026-10-17, reaffirmed). Embeddings via **`fastembed` 0.9.1** (Qdrant, Apache-2.0) — chosen over `sentence-transformers` after verification (research/phase3-brain-assumption-verification-2026-10-29.md): ONNX Runtime avoids the ~539MB CUDA-torch wheel on CI, 512-token context, higher MTEB retrieval score (62.17 vs ~56.26), same 384 dims. One small FastAPI app (`services/ai/app.py`): `/health`, `/context`, `/dedupe`, `/embed`. One pinned `requirements.txt` (fastapi 0.162.0, uvicorn 0.54.0, fastembed 0.9.1 — verified 2026-10-29). **Budget guards (adversarial H4):** pip cache via `actions/cache` on the pip dir; the brain loads only on runs that will write scripts (clips-lane/no-gen jobs skip it entirely); a 30-second readiness budget — if the model is not loaded within it, the run fails open per D6.
- **D2 — Chunked embeddings (resolves the 256-token truncation; re-adopts master plan §4).** `all-MiniLM-L6-v2` (served BY fastembed) truncates at 256 word pieces ≈ 190 words — a 1,300-word documentary loses ~87% embedded whole. **Therefore scripts are embedded as CHUNKED SUB-VECTORS (~200-token windows)**: documentary = one vector per chapter + one pooled whole-doc vector; Shorts = hook vector + points vectors + pooled. `/dedupe` compares **max chunk similarity** (not pooled-vs-pooled) — one matching scene is a match even if the rest differs. 384 dims verified; migration path in AC-P3-14.
- **D3 — Storage: Neon pgvector; **the DB is the corpus of record for script TEXT** (resolves adversarial Critical-1).** Table `script_memory` (id bigserial, channel_id, script_kind, chunk_kind (scene|hook|points|pooled|corpus|research), job_id, created_at, content_hash UNIQUE per (chunk_kind, hash), **chunk_text TEXT** — the actual script text per chunk, making this table the durable home of full script text, which state files never stored), performance jsonb, meta jsonb, model_id text, model_dim int, video_id text. Shorts script text (never durably stored today) gets persisted here at publish time per AC-P3-17. Exact-scan retrieval — no ivfflat/hnsw mandated at ~1k-10k vectors (revisit ~50k). Idempotency: hash-keyed upsert per AC-P3-13.
- **D4 — Corpus selection (review R-8):** embed **published AI-generated scripts only** — sources: `explainer/public/lf-*.json` (docs), and **Shorts scripts from the new publish-time persistence (D3)**. **Excluded:** `source:'fallback'` template scripts, gate-rejected scripts, failed-run outputs. Plus the research corpus (glob `research/*.md` — 86 docs today and growing; never hardcode a count) and template beat examples. Performance data: `reporting/logs/posts-log.json` + `state/report-stats.json`; richer refresh joins Phase 4's analytics snapshots.
  - **AMENDMENT (2026-10-29, live backfill evidence):** the original premise that lf-*.json docs are "already durable in git" is FALSE — they are intentionally gitignored (`.gitignore:104`). Resolution per D3: **the database is the corpus of record for script text.** Doc scripts reach memory via **publish-time embedding (AC-P3-2/17)** at videoId receipt; the backfill workflow indexes the **research corpus only** (CI: docs 0 by design — local lf-*.json hits are a local-file artifact). No git backfill of docs; no re-indexing premise.
- **D5 — Write-time flow (walk model corrected per adversarial R-4; embed timing corrected per Critical-2).** The walk loop lives INSIDE `callScriptBrain` (youtube-engine.mjs:477-493) — deepdive calls it once. Wiring: (1) `/context` queried at prompt assembly (engine prompt build; deepdive LONG_PROMPT call at yt-deepdive.mjs:230) — retrieved ids + performance recorded in job output; (2) `/dedupe` wired as a new injected hook in `callScriptBrain` (`checkDup(parsed) => {blocked, topMatchId, score}`), inserted between shape validation (youtube-engine.mjs:488) and return (:489); a BLOCKED verdict bypasses `SHAPE_RETRY_CLASSES` (parse_error/empty_response) as a THIRD re-walk reason; walks 2+ append guidance **naming the top match** ("your previous video 'X' covered this — vary the hook and examples"); (3) **embedding happens ONLY after the video survives to a real videoId** (upload accepted — see AC-P3-2 revision), all chunks of one script in a single all-or-nothing transaction. **Exhausted-walks terminal:** all walks BLOCKED → Shorts: `source:'fallback'` terminal → slot skipped at yt-daily.mjs:244 (fail-closed, no publish); doc: `llmScript` throws → nonzero exit → episode retried next doc day. Brain-unreachable → never halts (AC-P3-5).
- **D6 — Failure policy (explicit supersession, resolves review R-3 — upgraded by owner-relevant tiering):** brain/pgvector/embedding UNREACHABLE → fail-open everywhere with one warning (never dark — AC-P3-5), EXCEPT finance-gated templates: when the template's registry meta has `review_required` containing 'finance', an unreachable dedupe gate BLOCKS (fail-closed — never risk a policy-violating publish). Brain UP and dedupe verdict BLOCK → fail-closed for templates with finance in `review_required`, fail-open-with-WARN-verdict otherwise (recorded, AC-P3-16). Supersedes master plan §4's uniform fail-open; marked as supersession per review discipline.
- **D7 — CI-only runtime + cost guards (owner requirement AC-P3-6; adversarial H4 mitigations):** sidecar spawned inside CI jobs (localhost) like existing Python steps; CPU-only wheels (fastembed = ONNX — no torch at all); pip cache via `actions/cache` on the pip directory; fastembed model cache via `actions/cache` on its model dir with cold-start fallback per D6; the brain loads ONLY on runs that write scripts (clips-lane/no-gen jobs skip it entirely); a 30-second readiness budget — model not loaded in time → fail-open per D6; one-time backfill + re-index = `workflow_dispatch` jobs. Zero personal-machine steps anywhere (embed/query/migrate/backfill all dispatchable as CI workflows).
- **D8 — Thresholds from the registry (rewritten per review R-1):** NEW registry meta fields `variation_threshold` (number, default 0.85 cosine, validated by preflight like other meta) + `cross_channel_threshold` (default threshold + 0.05). Template identity is threaded into the dedupe call via the pipeline (slug → template id → registry meta); legacy/unassigned channels use the 0.85 default. Thresholds are DATA — no code edit to tune.
- **D9 — Node↔Python HTTP contract pinned (review R-12):** JSON schemas for /context (in: channel, kind, topic, k; out: [{id, score, performance, excerpt}]), /dedupe (in: channel, kind, template_id, chunks[], threshold; out: {verdict, score, top_match_id, neighbors[]}), /embed, /health — pinned as shared schema files referenced by both sides. **Similarity convention pinned: vectors stored normalized; pgvector `<=>` returns DISTANCE = 1 − cosine similarity; the gate is `similarity ≥ threshold` blocks.** A unit test pins the convention — an implementer flipping it silently would invert the gate.
- **D10 — Dropped audit decisions, explicitly marked (review R-13):** Anthropic contextual-retrieval prefixes, hybrid tsvector/RRF retrieval, and Ragas eval — NOT in Phase 3 (the last replaced by the paraphrase-fixture quality eval). Exact-scan retrieval, no ANN index at ~1k-10k vectors (revisit ~50k). Embedding model supersedes the audit's paid `text-embedding-3-small` (zero-cost requirement; re-embed warning carried into AC-P3-14).
- **D11 — Connection & cron math (adversarial H5):** the db adapter stays capped at 5 connections; 15 simultaneous jobs would attempt ~75 against Neon's ~100 ceiling — therefore per-channel cron offsets are STAGGERED (no two channels share an exact minute; the existing staggered-cron pattern extends to new channels), and the brain's DB access goes through the same capped client. Stated math: 15 jobs × ≤5 connections, staggered starts ≤ 15 concurrent — within ceiling.
- **D12 — Canonical fingerprint (adversarial H3):** ONE shared hash function (canonical JSON of the normalized script text + chunk kind) is used by BOTH the write-time embed and the weekly indexer — the same script can never receive two fingerprints. The weekly indexer's job is then only performance refresh (AC-P3-13).

## Testing Decisions

- Unit: embedding determinism, chunking windows, indexer upsert semantics (AC-P3-13), canonical fingerprint equality (D12: same script through both paths → same hash), similarity scoring + the distance/similarity convention, threshold gating incl. template-meta thresholds, fail-open paths (brain down, pgvector down, empty index, model mismatch per AC-P3-14), corpus-selection exclusions (fallback/gate-rejected excluded) — fixture vectors, no live Neon in CI.
- **Gate-quality fixture eval (replaces the dropped Ragas eval, per review R-15):** a known paraphrase duplicate ("37 billion" vs "thirty-seven billion" — the audit's exact example) must BLOCK; an unrelated same-niche script must PASS; a cross-channel same-template pair must WARN. These fixtures travel with the suite forever.
- Integration: one CI-job test spawning the sidecar, embedding fixture scripts, and round-tripping /context + /dedupe against a disposable pgvector (Neon branch or local pgvector container).
- Live E2E: the documentary run — script written with context provenance in the job log + a dedupe verdict recorded; near-duplicate fixture script BLOCKED; **the routed provider visible in both the job log and the usage ledger** (Phase 2's proven chain, re-exercised through the brain).

## Acceptance Criteria (EARS-style)

- AC-P3-1: When the indexer runs against an unchanged corpus, it shall insert zero rows; when the corpus or performance data has changed, it shall insert new hashes and update existing rows' performance/meta in place (no duplicate row, no re-embed of unchanged content).
- AC-P3-2 (revised per adversarial Critical-2): When a video receives its YouTube videoId, the system shall embed ALL of its chunks in ONE all-or-nothing transaction (no partial chunk sets), cloud-side — and shall never embed scripts that died before upload (no ghost vectors).
- AC-P3-3: When a generator starts writing, it shall query `/context` and record the retrieved past-script ids + performance in the job output (provenance).
- AC-P3-4: When a new script's max chunk similarity to a past script of the SAME channel exceeds the template's `variation_threshold`, the system shall BLOCK (consume the escalation retry); when ALL escalation walks return BLOCKED, the script phase shall fail using the lane's existing terminal (Shorts: slot skipped via the `source:'fallback'` gate at yt-daily.mjs:244; doc: nonzero exit, episode retried next doc day), and a terminal BLOCKED verdict (top match id + score) shall be durably recorded (AC-P3-12).
- AC-P3-5: When the brain, pgvector, or embedding model is unreachable, the system shall proceed without memory (fail-open), log one warning naming the failure class, and fire one ntfy alert — generation never halts for memory-AVAILABILITY reasons (distinct from AC-P3-4's brain-up-policy-block).
- AC-P3-6: When any memory operation runs (index, embed, query, migrate, backfill), it shall execute inside CI/cloud jobs using only requirements.txt + repository files + environment variables — zero steps on a personal machine.
- AC-P3-7 (rewritten per review R-1): When `/dedupe` evaluates a script for a channel with an active template assignment, the threshold shall come from that template's registry `variation_threshold` field (NEW registry field, default 0.85); for legacy/unassigned channels it shall use the 0.85 default.
- AC-P3-8: When retrieval returns exemplars, the system shall attach their performance data (views/retention where available) so the writer can weight what worked.
- AC-P3-9: When the research corpus is queried, results shall be usable as citation sources (path + doc id recorded in the script's provenance).
- AC-P3-10: When the sidecar receives `/health`, it shall report model-loaded + pgvector-reachable states for CI preflight checks.
- AC-P3-12: When `/dedupe` returns any verdict (PASS, WARN, or BLOCK), the system shall write one row to a Neon `dedupe_verdicts` table (channel_id, script_kind, job_id, verdict, top_match_id, score, threshold, created_at); a failed write shall degrade to one log warning and never halt generation. This table doubles as the variation-evidence ledger for YouTube reviews.
- AC-P3-13: When the indexer encounters an existing content_hash, the system shall update that row's performance and meta in place (no duplicate row, no re-embed); it shall insert rows only for new hashes and embed only when the hash or model stamp is new.
- AC-P3-14: When the pinned embedding model id or dimension changes, the system shall re-embed the entire corpus into the new dimension before any /dedupe query runs, and /dedupe shall fail open with a warning when it detects rows whose model stamp differs from the current model.
- AC-P3-15: When the indexer selects scripts to embed, the system shall include only published AI-generated scripts and shall exclude fallback-template scripts, gate-rejected scripts, and scripts from failed runs.
- AC-P3-16: When a new script's max similarity to a DIFFERENT channel's same-template script exceeds the cross-channel band (template threshold + 0.05 unless registry-specified), the system shall record a WARN verdict with the match id — it shall not BLOCK unless the template's registry meta marks cross-channel convergence as blocking.
- AC-P3-17 (new — durability of script text, resolves adversarial Critical-1): When a video is published (videoId received), the system shall persist the full script text (per-chunk `chunk_text`) into `script_memory`, making the database the durable corpus of record — including Shorts scripts, whose full text is never stored anywhere else today.
