## 🔴 Critical (fix today)

### C1. CI Doctor is completely offline — untracked import crashes every run
- **File:** `ci-doctor.mjs:13`, missing `lib/workflow-validator.mjs`
- Commit `8f9cc35` (2026-10-17 01:26 +0500) added `import { validateWorkflows } from './lib/workflow-validator.mjs'` but **never committed the file** (`git log --all -- lib/workflow-validator.mjs` is empty; `git ls-tree origin/main lib/` lacks it; it is untracked locally).
- The tracked test `tests/workflow-validator.test.mjs` imports the same missing file — it also cannot run from a fresh clone.
- **Evidence:** CI Doctor workflow failed `ERR_MODULE_NOT_FOUND` on runs 38977603106 (Oct 16 22:45 UTC) and 39014442329 (Oct 17 07:39 UTC): `code: 'ERR_MODULE_NOT_FOUND', url: 'file:///home/runner/work/automation/automation/lib/workflow-validator.mjs'`. The one watchdog meant to catch silent outages is itself silently out.
- **History worth knowing:** the pre-refactor inline validator falsely reported **all 20 workflows** as `BROKEN_WORKFLOW` ("Cannot read properties of undefined (reading 'load')") in the report committed by CI itself (7e14849, Oct 16 16:20) — root cause was js-yaml v5 having **no default export** (`typeof m.default === 'undefined'`, `load` is a named export; verified via `node -e`). The current local validator handles this (`yamlMod.default || yamlMod`) and runs clean (`valid: true, 0 problems`) — it just needs to be committed.
- **Fix:** commit `lib/workflow-validator.mjs`. One `git add` + push turns CI Doctor green again.

### C2. Every successful TikTok post is double-posted ~3h later
- **File:** `zernio-tiktok-publisher.mjs:236,249`
- Line 236 pushes the **post ID** (`postedIds.push(postId)`) on direct-publish success; line 249 checks `postedIds.includes(accountId)` — always false because `postedIds` never contains account IDs. After every success, flow falls into the "capacity full" reschedule branch (line 254) and creates a scheduled duplicate of the same video on the same account (`ZERNIO_TIKTOK_RESCHEDULE_HOURS=3` default; neither mitigation env var is set).
- **Impact:** every reel published via `publishToTikTok` appears twice on TikTok. Runs 4×/day (`.github/workflows/tiktok-post.yml:50`) plus inside the daily channel pipeline.
- **Fix:** push `accountId` (semantics: "this account is served") — one-line change, plus a regression test.

## 🟠 High

### H1. yt-daily's "never crash" design silently loses the day and defeats verify-run
- **Files:** `yt-daily.mjs:14-15` (log-only `uncaughtException`/`unhandledRejection` handlers), whole loop is top-level `await`, `saveState` only at line 315.
- A mid-loop throw suspends module evaluation → handler logs → **process exits 0** → later slots AND `saveState` never run. `channel-pipeline.mjs` then marks `shorts = true`, and `verify-run.mjs` "verifies" **yesterday's** `st.lastVideos` (state was never saved) → prints OK. The Sept-20 audit's proof-of-publication fix ("success lie") is bypassed by exactly this path. The sweeper also reports a failed heal as healed when yt-daily exits 0 (`sweeper.mjs:109-110`).
- **Fix:** wrap the per-slot loop in try/catch (per-slot isolation + hard-fail after loop), and make verify-run receive *this run's* claimed videoIds explicitly.

### H2. The pre-render duplicate-title gate can never fire (and the dup gate fail-opens)
- `yt-daily.mjs:206` calls `findDup(script.title, …)`, but **no `generateYouTubeScript` return path contains `title`** (`youtube-engine.mjs:512,556,575,593,610,634` — spread of `parsed` + points/closing/thumbHeadline/source only; the prompt never requests one). `findDup(undefined,…)` → `normTitle(undefined)=''` → always null. Near-dup scripts burn a full script+render before the post-render meta gate rejects them.
- Compounding (`lib/dup-gate.mjs:41-52`): `recentUploadTitles` swallows **all** API errors returning `[]` — the exact correlated condition (quota exhaustion) under which the Oct-1 near-dup collapse happened disables dup checking entirely. The 60-deep `state.titleHistory` written at `yt-daily.mjs:312` has **zero readers** (grep) — the durable fallback is dead code.

### H3. `--topup` heal suppresses the next day structurally (under-production / zero-days)
- `yt-daily.mjs:303-308`: `suppressNext = TOPUP_N > 0 && results.length > 0`, but `results` counts **gate rejections** (`{videoId:null, gateRejected:true}` pushed at 240/247) — a heal where every render was rejected still suppresses tomorrow's cron → a full day with zero uploads (42h recovery). For multi-slot channels a *partial* heal suppresses the whole day, causing an oscillation that never returns to full cadence.

### H4. Quote Quarry's daily FB image posts go to the retired page
- `yt-daily.mjs:277` hardcodes `'quotequarry': '108044922375174'` (Strategic Silence, retired); `fb-crosspost.mjs:20-25` and `daily-excel-report.mjs:24` use `'114550268199751'` (Reliq North, 8.6k followers, the 09-20 swap). yt-daily's inline copy was missed → QQ frames post to a dead page daily.

### H5. `dropChannelKeys` deletes the shared key too — "shared key covering" is false
- `lib/channel-keys.mjs:39-61` (`applyChannelKeys` **overwrites** `env[envName]` with the channel key, shared value lost) and `:117-121` (`dropChannelKeys` does `delete env[envName]` while its comment says "shared keys resume"). After a dead-channel-key drop, the provider has **no** key at all for the rest of the run; Pixabay/Pexels silently degrade to stale cache while ntfy claims shared coverage.
- Related: `sweeper.mjs` calls `applyChannelKeys` but never `checkChannelKeys`/`dropChannelKeys` — heal runs skip the dead-key guard entirely (only `channel-pipeline.mjs:52-63` has it).

### H6. `longvideo/stage-docv2.mjs` is dead on arrival — parse-time SyntaxError
- Lines 11 and 68 both declare `const FFPROBE = …` → `node --check` gives `SyntaxError: Identifier 'FFPROBE' has already been declared`. The documented DocV2 entry point can never run (make3v2.mjs duplicates the flow, which is why nobody noticed).

### H7. edge_batch.py discards successfully re-synthesized speech — beat becomes 8s of silence
- `explainer/edge_batch.py:78-93`: `ok = True` is set once; the `except` sets `ok = False` and **nothing ever resets it**. A beat that fails attempt 1 but succeeds on retry still hits `if not ok or …` → `silence(mp3, 8.0)` **overwrites the just-written good mp3** and wipes `words`. Affects every consumer (tts.mjs, storyboard.mjs, make3v2.mjs, stage-docv2.mjs, both demos).
- Related in the same file (`:72-75`): the resume path returns `words: []` for cached beats — captions lose word sync on any re-run (tts.mjs has no carry-over; symptom family of tracker #17 but different engine/mechanism).

### H8. storyboard.mjs drops magnitude multipliers — "37 billion dollars" renders as "$37"
- `longvideo/storyboard.mjs:189-194`: `mult` (1e9/1e6/1e12) is computed from the matched suffix but **never applied to `num`**; the money branch formats raw `num`. Repro: `"The company lost 37 billion dollars"` → `big = "$37"`. Also skews the `num >= 20` gate ("12 billion" silently loses its number beat). The spelled-out branch (201-210) is correct — only digit+magnitude sentences (the most common form) are wrong.

### H9. weekly-compilation's duplicate-upload guard is dead code
- `weekly-compilation.mjs:198` checks `v.snippet?.title` / `v.snippet?.publishedAt`, but `fetchTopShorts` (lines 64-69) maps videos to `{ videoId, views, headline, description }` — `snippet` is dropped. `dup` is always `undefined` → a DAILY-mode re-run publishes a second identical compilation.

### H10. The TTS cache is text-blind and psych/explainer share one audio workspace
- `make-psych-demo.mjs:26-47` writes into the same `public/audio/beat-XX.mp3` + `tts-durations.json` used by `tts.mjs`; `edge_batch.py:69-75` resume keys on index + file size only (never text). Same text-blindness in `build-reel.mjs:35-45`, `storyboard.mjs:258-267`, `make3v2.mjs:65-71`: editing any narration line keeps stale audio under new text.

### H11. fb-crosspost never awaits the FB-native variant — posts the raw video, logs fake success, can crash mid-pass
- `fb-crosspost.mjs:153`: `buildFbVariant(videoPath, job.slug, variantPath)` is **not awaited** (async fn, `fb-variant.mjs:11`); line 158's `existsSync` check races ahead of ffmpeg → the **original untransformed video** is posted — the exact Meta-demotion the 09-20 variant feature was built to prevent. Line 154 logs success before render starts; an ffmpeg failure becomes an unhandled rejection that can kill the whole pass (batch try/catch can't catch it). Single-file mode (line 112) awaits correctly.

### H12. Studio: client-role flow toggle always 500s (TDZ)
- `studio/app/api/channels/flow/route.js:21-29`: the client-role ownership check references `slug` at line 23, but `slug` is destructured from the body at line 29 → `ReferenceError: Cannot access 'slug' before initialization` → every client PATCH (including pausing **their own** channel) 500s. ### H13. Studio: `/api/analytics` module-level 1h cache leaks cross-user data
- `studio/app/api/analytics/route.js:14,100-107`: `const cache = { at: 0, data: null }` is module-scope and the cache short-circuit runs **before** the per-user `slugsForUser` filter (line ~116). ### H14. Studio: YouTube-policy consent record is not persisted anywhere

### H15. `hyperframes-create.yml` dies on every dispatch — writes into a gitignored dir with no mkdir
- `.github/workflows/hyperframes-create.yml:36-38` writes `work/${{ inputs.job_id }}.brief.json`; `hyperframes/.gitignore` ignores `work/` and nothing creates it.
